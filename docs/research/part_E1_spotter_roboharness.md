## 2. Spotter（arXiv 2609.36808 v1，2026-09-29）【全文】

作者：Long Li\*、Qichao Zhao\*、Yue Yang、Fan Xu、Zhe Wang、Alan Wee-Chung Liew、Chao Qu、Heng Tao Shen、Shirui Pan†（\* 共同一作，† 通讯）。单位：Griffith University（Li、Wang、Liew、Pan）、清华交叉信息院（Zhao）、MainCode（Yang）、腾讯（Xu）、复旦（Qu）、同济（Shen）。作者与单位的对应取自项目页，arXiv HTML 丢了上标。资助方：MainCode（致谢）。

### 2.1 卡片

- **问题**（§1，§3.1，Fig. 2）：
  - 具身模型不会纠正自己的错误。由 oracle 在失败点打断，再给 3 次机会，纠正率也不到一成（每设置 320 次失败抓取，Fig. 2(a)）：
    - 重采样：Cosmos 7.50%，π0.5 8.75%；
    - 语言反馈（只测 π0.5）：9.69%；
    - 恢复数据微调：8.13% / 8.44%。
  - 测试时打分器在失败后失去排序能力（Fig. 2(b)）：Cosmos value head 0.66 → 0.57，Consistency-Consensus 0.55 → 0.45（读图）。只看图像的 VLM judge 也接近随机：GPT 57% → 53%，Qwen 53% → 51%（§3.1）。
  - 已有 VLM-led 设计（Harness VLA 等）让 VLM 每步规划，VLM 处在关键路径上（§1，§2，Table 1）。
- **架构**（§3.2，Fig. 3，Table 2，Table 3，附录 B，附录 C）：
  - 冻结的具身模型 π 持续逐块执行：
    - Cosmos Policy：2B，每块 16 步；
    - π0.5：输出 50 步，执行前 25 步。
  - **筛查器 S**：本地 Qwen3.8-27B-FP8，对每次检查涵盖的块给 0–10 的风险分。下列任一情况记 flag：
    - 风险分 ≥ 3；
    - 筛查调用失败或返回无效值；
    - 任一块内夹爪闭合到 12 mm 以下（mug 任务阈值 4 mm），即"空夹爪证据"。
  - 筛查频率：Cosmos 每 2 块（32 步）一次，π0.5 每块一次。
  - **judge J**：Qwen3.8-27B 或 GPT-6 Astra（Responses API，medium reasoning，服务端续接对话）。触发条件：
    - 连续 2 次 flag（short-context 配置为 1 次）；
    - 新出现空夹爪证据，且前两次检查内没有干预过，则立即调用；
    - 每次修复之后的下一个监督窗口强制做一次"只观察"的检查。
  - judge 输出 $(v,\delta,e,p)$：判决 v ∈ {ok, intervene, giveup}、自由文本诊断 δ、可观察的预期 e、原语计划 p（Eq. 3）。
  - **有界异步**：π 最多领先检查 K 块（Eq. 1）。Cosmos K=4，π0.5 K=2，即最多落后 64 / 50 个策略步。
  - **执行器**：把 judge 给的像素目标用该相机的深度图提升到 3-D（单像素深度）。深度只给执行器用，不给 VLM 看（附录 C）。
  - **预算**：每次修复最多 8 个原语、3 段；每回合干预上限 3 / 8 / 8（Table 3）。修复动作也计入步数上限 T（官方上限 × 1.8）。
- **什么在进化**：测试时**不进化，是纯推理时系统**，检索的是冻结的经验库。
  - 离线学习阶段：在训练数据或非测试 seed（seed 195）上，让 GPT 复位仿真、重试，并把发现总结成"通用经验"库（发布版 77 条），评测时冻结、只检索（§3.2 "Physical reset and learning"，附录 B）。
  - 1-shot 示例库同样冻结。
  - 策略权重不变。
- **改进信号**：
  - 学习期：GPT 在复位重试中观察到的结果。论文称监督者从不看到成功信号（§4.1）。仓库文档称学习期以 `--mask-oracle` 运行，服务不返回 `object_xyz`、`is_grasped`、`task_success`。
  - 在线：judge 自己写的预期 e 在下一个窗口是否成立（§3.2）。
- **接受门控**：
  - 论文：去掉特权信息和任务特定信息后入库；由谁执行这一过滤，**未报告**（附录 B）。
  - 仓库文档（`memory_bank/README.md`）：学习回合只把草稿写进 `inbox/`，由 `merge-inbox` 工具发布：
    - 新 id 直接发布；
    - 同 id 同正文记为一次佐证，合并证据；
    - 同 id 不同正文归档到 conflicts，等人工审阅。
  - 置信度阶梯：证据格 ≥ 3 且来自 ≥ 2 个不同任务 → verified；≥ 2 格 → probable。
  - 没有"经回放或评测验证才入库"的门。**推断**：库里的条目没有以成功率作为准入依据。
  - 测试时对修复本身没有门，只有"预期核对"规则。
- **关键结果**：
  - Table 4（RoboCasa，1,200 回合，All 列）：
    - 基线：1.0× 上限 Cosmos 66.7 / π0.5 62.5；1.8× 上限 67.9 / 64.3。
    - fixed retry（失败后退回并让 VLA 重试，不用 judge）：筛查器触发 66.9 / 62.1，oracle 触发 67.1 / 63.1。
    - Spotter (Qwen)：short 69.3 / 67.1，full 71.7 / 68.4，1-shot 71.8 / 70.4。
    - Spotter (GPT)：有筛查器 70.0 / 68.8，无筛查器 72.0 / 70.8，1-shot 73.5 / 71.8。
    - Harness VLA (Qwen)：有特权信息 71.3 / 69.1，无特权信息 65.2 / 60.5。
    - 增益主要来自 pick-and-place（GPT 1-shot：+10.3 / +9.0）。
  - Fig. 4(b)（RoboTwin 2.0 Hard，读图）：
    - π0.5：1.0× 45.6，1.8× 47.2；Spotter Qwen 51.2，GPT 57.0。
    - 对比方法 GR00T-N1.7 20.7、LingBot-VLA 50.4 取自 Harness VLA 论文（50 任务 × 5 seed，协议不同）；X-WAM 25.8 由作者自跑（附录 B）。
  - Fig. 5（Franka）：见 §1.1。
  - Fig. 7、§5：
    - judge 干预的回合中约 85% 是策略单独会失败的（Qwen）；GPT 1-shot 读图接近 100%。
    - 单次修复的纠正率约 10%–20%：GPT 1-shot 19.2%，Qwen 1-shot 13.5%。
  - §4.4、Table 6：成功回合只比策略单独多 13 s（Cosmos）/ 16 s（π0.5）；失败回合耗时是单独运行的 4.2× / 5.0×。
- **优点**：
  - 常规路径上不等 VLM：筛查器与策略并行，每回合掩盖 36–38 s（Cosmos）/ 29–30 s（π0.5）的监督时间（§4.4）。
  - 不训练策略，不用特权信息，本地 Qwen 也有正增益（Table 4）。
  - judge 直接用原语修复，不把语言指令交还给 VLA。这与 §3.1 的发现一致：VLA 听不懂纠错指令，Cosmos 甚至不接受非官方指令。
  - "写下预期 → 下一窗口核对 → 没成立就换一种修复，而不是换偏移量"的规则（§3.2）。
  - 用 Retreat 把机械臂退回记录过的位姿来代替仿真回滚，因此能上真机（§3.2）。
  - 对照与处理用同场景、同指令、同步数预算（§4.1）。
- **缺点与风险**：
  - 仿真增益中等：最佳配置（GPT 1-shot）+5.6 / +7.5，零样本 Qwen 只有 +3.8 / +4.1（Table 4）。
  - 失败回合很贵：GPT 无筛查器时 Cosmos 失败回合 1,030k token（Table 6）。
  - 单次修复只纠正约 10%–20% 的错误（Fig. 7）。
  - 不可逆损坏（物体掉出视野等）不在范围内（§3.2）。
  - 真机每任务只有 10 次，配置为 GPT 1-shot。真机用的经验库或示例从哪来、成功如何判定、耗时多少，均**未报告**。
  - Harness VLA 是用 Qwen 重跑的，轮数从 100 改为 40、步数预算改为 5,000，不是原论文的 Codex / Claude Code 配置（附录 B）。
  - RoboTwin 的部分对比数字来自其他论文，协议不同（附录 B）。
  - 阈值是按任务族手调的启发式：风险分 3、夹爪 12 mm / 4 mm（附录 B）。
  - 仓库与论文有出入（仓库文档）：
    - README 写 `spotter.sh` 默认跑**同步**监督（`ASYNC_SCREEN=0`），有界异步要设 `ASYNC_SCREEN=2 ASYNC_K=2`；论文附录 B 写"默认是有界异步"。论文数字是用哪种模式跑的，从公开材料无法确定。

### 2.2 VLM 与 VLA 的接口（Spotter）

1. **VLM 输出什么**（§3.2 Eq. 2–3，Table 2，附录 B–C）：
   - 筛查器只输出 0–10 风险分（最多 120 token，温度 0）。
   - judge 输出判决 ok / intervene / giveup、一句自由文本诊断 δ。intervene 时再给：
     - 可观察的预期 e，例如"抬臂时夹爪保持张开 > 20 mm"；
     - 原语计划 p，最多 8 个原语、3 段。可用原语：
       - Move to point：目标是指定相机视图里的像素 (r, c)，或世界坐标 (x, y, z)，可附垂直偏移；
       - Move by offset、Lift、Rotate wrist、Set gripper；
       - Retreat：退回到 judge 选的、之前记录过的位姿；
       - Move both arms；
       - Act：让 π 运行指定块数；
       - Hand back：结束接管。
   - 不给 VLA 下自然语言子目标，不写代码，也不对动作块做执行前的接受/拒绝（它审查的是已经执行的块）。
2. **VLA 输入**（§3.2 问题定义，§2，§3.1）：
   - RGB 图像 $I_t$、机器人状态 $q_t$（末端位姿与夹爪状态）、任务指令 ℓ，输出接下来 H 步动作。
   - Spotter 不改指令，不给 VLA 加记忆或历史；论文原话是不把计划或指令交还给 VLA。
   - 指令就是基准原始任务指令，长度未报告。
3. **时域**（附录 B，Fig. 3，Table 5）：
   - 筛查器：Cosmos 每 2 块（32 步），π0.5 每块（25 步）；π0.5 short-context 配置每 2 块（50 步）。
   - judge：事件驱动，不在开局调用，也不按固定节拍调用；修复后的下一个窗口必查一次。
   - VLA 在筛查和 judge 思考期间继续执行，直到错误被确认或领先达到 K 块（Cosmos 最多 64 步，π0.5 最多 50 步）。
   - 实测每回合 judge 调用次数（成功 / 失败回合，Table 5）：
     - Cosmos + Qwen full：0.6 / 10.9；
     - π0.5 + Qwen full：0.6 / 9.9；
     - Cosmos + GPT 有筛查器：2.5 / 13.1；
     - Cosmos + GPT 无筛查器：5.5 / 17.8。
4. **停止条件**（§3.2 Eq. 1，附录 A–B）：
   - VLA 只在两种情况下暂停：judge 确认错误（intervene），或领先达到 K 时停在块边界等检查追上。
   - 整个回合在成功条件 $\mathcal{G}$ 成立时结束（评测框架读仿真谓词，监督者不知道），或在步数上限 T 时结束（官方上限 × 1.8，修复动作也计入）。
   - 修复中由 judge 在 Act 原语里指定 VLA 跑几块。
   - 触发筛查 flag 的信号有三类：视觉风险分、夹爪开度（本体）、筛查失败。
5. **验证者**（§3.2，附录 A）：
   - 任务成功：只由评测框架的仿真谓词判定，用于打分和终止，从不告诉监督者。
   - 修复是否成功：由同一个 judge 判定。每段修复后它看新图像和执行日志，决定继续、宣布修好或放弃。随后的下一个监督窗口是强制的只观察核对，它必须先说预期 e 是否成立：
     - 成立，则不许重复同样的修复；
     - 不成立，则下一次必须换一类修复，不能只换偏移量。
   - VLA 没有自述。VLM 自己宣布"修好"不直接算数，要经下一窗口核对，但核对者仍是同一个 judge，没有独立验证器。
   - 判据：多相机时序拼图、遥测、动作历史、原语执行日志。
6. **失败后的处理**（§3.2，Table 2，Table 4）：
   - **VLM 直接接管**，用原语计划修复。默认不让 VLA 重试同一段；对照实验表明"退回 + VLA 重试"无效（fixed retry 行与基线持平）。
   - 不回滚仿真。可用 Retreat 把机械臂退回接管时的位姿或抓取前锚点（每个块边界都记录臂位姿）。
   - 接管时的输出：末端目标（像素加深度提升到 3-D，或世界坐标）、相对位移、腕部转角、夹爪开合、双臂同步移动。可以通过 Act 再调 VLA。不输出关节角。
   - 每次修复和每回合都有预算上限。judge 判 giveup 后系统怎么做，**未报告**。
7. **交还**（§3.2，Fig. 1；仓库文档）：
   - 交还条件：judge 输出 Hand back，或宣布问题已修好；π 从修复后的状态继续，没有回滚。
   - 交还前**没有**专门把机器人挪到"VLA 熟悉状态"的步骤，也没有分布检查。
   - 最接近的做法：Retreat 到 VLA 自己走过的位姿（接管位姿或抓取前锚点）。Fig. 1 的例子是先退回失败前的位姿，再向右平移对准青柠。
   - 交还后的下一个窗口由 judge 强制核对。
   - 仓库经验库里有一条 probable 级经验："A grasp verified by lift and lateral tests can still drop within the first chunks after handoff"（仓库文档）。
8. **记忆**（Table 3，附录 B；仓库文档）：

     - 回合历史 $h_i$：遥测保留最近 3 / 10（π0.5）/ 40（Cosmos）块，更早的做摘要；

作者（v3）：Jinbang Huang（华为诺亚方舟）、Zhiyuan Li（UBC）、Yuanzhao Hu（多伦多大学）、Ran Qi（UBC）、Yixin Xiao（诺亚方舟）、Mark Coates（McGill）、Tongtong Cao（Department of Foundation Model, 2012 Labs）、Zhanguang Zhang（诺亚方舟）、Yingxue Zhang（诺亚方舟）。脚注："†Equal contribution"，"∗Work done during an internship at Huawei Noah's Ark Lab"。哪位作者对应哪个符号，HTML 里丢失了；通讯作者在 HTML 和项目页中都未标出。项目页：robo-harness.com，只有论文链接，没有代码链接。

### 3.1 卡片

- **问题**（§1，§3）：长任务需要多个异构策略（VLA、WAM、RL、TAMP）接力，有两个难点：
  - 各策略的能力边界不确定，且随上下文变化，因此分解与分配要一起做；
  - 交接时分布不匹配：上一个策略的终止状态可能落在下一个策略的可执行区域或输入分布之外，导致连锁失败。
- **架构**（§4，Fig. 1，附录 C）：
  - **编码 agent**：Codex，底层模型 GPT-5.5（§5）。负责分解任务、给子任务分配策略、按需调用辅助技能并解读其结构化输出、修订计划。
  - **策略即技能**（§4.3）：每个策略保留原生实现和输入输出，不共享动作表示，各配一张"policy card"。卡上记录能力、接口要求、约束、假设、训练任务、执行统计。编码 agent 还可以直接读策略的实现代码。
  - **策略库**（附录 C.3.1，Table 3）：
    - π0.5：LIBERO 系列用官方 `pi05_libero`；RMBench 和 BEHAVIOR-1K 用自训权重。
    - Faster-WAM：用作者发布的训练流程在 LIBERO 上训练。
    - RLinf OpenVLA-OFT：GRPO 后训练，checkpoint 为 `RLinf-OpenVLAOFT-GRPO-LIBERO-90`。
    - TAMP：PDDLStream + FF 规划器。高层动作有三种落地方式：RRT（OMPL）位姿运动规划；VLM 视觉控制（输出 8 个平移方向 + 6 个旋转方向的网格调整）；基于记忆的轨迹增强。
    - LIBERO、LIBERO-Plus、RMBench、BEHAVIOR-1K 只用 π0.5 + TAMP；LIBERO-LoHo 和消融实验四个策略全开。
  - **理解技能**（§4.1，附录 C.1），共 5 种：
    - 不确定性评估：物体位姿在滑窗内的均值和方差；
    - 视觉上下文：SigLIP2 + DINOv2 余弦相似度与记忆比对；
    - 语义上下文：BGE-large；
    - 输入质量：曝光、锐度、对比度、熵；
    - 状态–策略兼容性：借用 Memory Bridge 的支撑域和进度估计器。
    - 论文强调这些输出只是证据，不是校准过的成功概率。
  - **记忆技能**（§4.2）：每个策略一个情节记忆库，只存成功轨迹；另有一份完整执行日志 H，成功和失败都记。
  - **Memory Bridge**（§4.2.2，附录 C.2）：交接前把机器人移到下一个策略记忆所支撑的位形。细节见 §3.2 第 7 条。
  - **进化技能**（§4.4，附录 C.3）：
    - 策略适配：TAMP 用 SIMPACT 调抓取位姿，用 PDDLLM 学新的逻辑表示；也调策略暴露出的超参数。
    - harness 精修：Codex 在线改编排代码（接口、路由、协调逻辑），并调检索数、Memory Bridge 阈值、桥接轨迹接受标准。
    - 元数据更新：改写 policy card。
- **什么在进化**（§4.4，附录 C.3，§5）：评测过程中在线变化的有：
  - 编排代码与编排参数；
  - TAMP 的抓取参数与 PDDL 领域；
  - policy card；
  - 各策略的情节记忆库（成功执行会追加进去）。
  - 学习型策略不重训，也不联合重训。经验**只在同一任务的多次试验之间保留**（§5）。
- **改进信号**（附录 C.3）：执行日志 H 里的执行轨迹、运行时错误、"期望结果与观测结果不一致"。持续失败会触发进化。
- **接受门控**：
  - 改过的实现"经后续执行验证后才保留"，验证通过的改动跨回合持续（附录 C.3，§4.4）。具体判据（几次试验、什么阈值）**未报告**。
  - 参数更新是方向性网格搜索：编码 agent 只选"增 / 减 / 保持"，由单独的调参模块映射到离散网格上的值（附录 C.3）。

### 3.2 VLM 与 VLA 的接口（RoboHarness）

   - 需要时调用 Memory Bridge；
   - 对理解、记忆、进化技能的调用，以及对结果的解读和计划修订；
   - 进化时还输出：编排代码的修改、参数方向（增 / 减 / 保持）、policy card 的修改。
   - 它不输出底层动作。计划以代码形式还是工具调用形式发出，**未报告**，论文只写"coding agent invokes these skills on demand"。
   - 交接位姿 s\*（末端位姿 + 关节）由 Memory Bridge 算法计算，不是 LLM 生成。
   - TAMP 内部"VLM 视觉控制"输出的是网格方向调整，用哪个 VLM **未报告**。
2. **VLA 输入**（§3，附录 C.3.1）：
   - 由当前观测 o_t 构造各策略的原生输入，加上子任务指令 g_t。也就是每个子任务换一次 prompt。
   - 指令长度未报告。
   - 不给 VLA 喂记忆或历史（论文未提到这样做）。记忆的作用是先把机器人摆到合适位形，而不是作为 VLA 的输入。
   - 另：TAMP 的"基于记忆"配置会在每次策略调用前，先重放检索到的示教片段的前 40%（β = 0.4）。这句话出现在 TAMP 条目下，原文是 "each policy invocation is preceded by replaying the leading fraction (β = 0.4) of a retrieved demonstration segment"，作用范围没有更多说明。
3. **时域**（§4.2.2，附录 C.2，§7）：
   - 编码 agent 在开局做分解，之后在**子任务边界**被调用：每次策略执行或桥接结束后重评观测和任务上下文，再调用下一个策略或修改路由。持续失败时触发进化。
   - VLA 一段执行多少步：**未报告**。π0.5 微调配置的 action horizon 是 50（附录 C.3.1），执行时用几步未报告。
   - 真机：每个任务 20–30 个子任务，推理或规划调用平均每次 4.6 s，每回合累计 67.4 s。**推断**：约 15 次调用 / 回合（67.4 ÷ 4.6）。这比子任务数少，说明并非每个子任务都调用一次，但论文没有解释。
4. **停止条件**：
   - 单个策略段由谁、凭什么信号停止：**未报告**。
   - 已知的时间上限：真机每回合 10 分钟（§5），超时是主要失败模式（§7）；Memory Bridge 候选搜索 10 s 上限（附录 C.2）。
5. **验证者**（§4.1，§4.2.2，附录 C.2）：
   - 子任务完成由编码 agent 判断。它在每次执行后用理解技能重评。证据包括：
     - 图像；
     - 物体位姿估计（仿真为加噪真值，真机为 ArUco）；
     - 机器人状态；
     - 中间执行结果；
     - 运行时反馈与错误（执行日志记录的内容）。
   - 策略自身返回的终止或成功信号算不算数：**未报告**。"策略执行成功才写记忆"中的成功由谁判定：**未报告**。
   - 回合成功：用各基准官方指标（LIBERO-LoHo 进度分 / 成功率，RMBench 每回合二值，BEHAVIOR-1K 二值成功标准）。真机由谁判定：**未报告**。
6. **失败后的处理**（§4.2.2，§4.4，附录 B，附录 C.3）：
   - 编码 agent 修改路由或重新规划，把子任务改派给其他策略，不必从头重来。
   - 真机干扰下的表现：积木被重新藏起，就重新探索；结构被拆，就重评进度后重规划。
   - 持续失败时进化：从 H 检索相关日志，选择策略适配、harness 精修或元数据更新。
   - LLM **不直接接管底层控制**，动作总是经由某个策略或桥接用的运动控制器。是否重试同一段：**未报告**。
7. **交还 / 交接**（§4.2.2，附录 C.2，Fig. 2，Fig. 9，附录 B）：这是本文重点。
   - 时机：在两个策略之间"需要时"插入 Memory Bridge。触发规则**未报告**；只说状态–策略兼容性评估会提供"可能需要桥接"的证据。
   - 步骤：
     1. 用下一子任务 $g_{t+1}$ 和上一策略的终止观测，从**下一个策略的记忆库**检索 top-K 锚点；
     2. 沿每个锚点的轨迹双向扩展邻居节点（同一子任务、同一夹爪状态），以有符号时间偏移作标签，训练线性 pairwise ranking SVM 作为局部进度估计器；
     3. 在"离已检索状态 ≤ ε"的支撑域内采样候选状态，筛掉运动规划不可达的和进度分 < θ 的；
     4. 取 $f_{\text{score}} - \lambda C_{\text{motion}}$ 最大者（λ = 0.2）；
     5. 由现成运动控制器执行桥接轨迹。
   - 状态定义：末端位置 + 四元数 + 关节角，用该记忆库各维 min / max 归一化。
   - 桥接后由编码 agent 重评场景和任务，再调用下一个策略或改路由。下一个策略若执行成功，其轨迹写入它自己的记忆库。
   - Fig. 9 示例：分布外位形经桥接回到分布内。
   - 真机：发现积木被藏时，经 Memory Bridge 把控制交给 π0.5 开抽屉、探索；然后"控制交回 TAMP"。交回 TAMP 时是否也走桥接，**未明确**。
8. **记忆**（§4.2.1，附录 C.2，§5）：
   - **每策略情节记忆库**：
     - 只存成功轨迹，形式为按时间链接的节点；
     - 节点内容：图像观测、子任务指令、原始机器人状态 [末端位置 3 维, 四元数 4 维, 关节角]、夹爪状态、SigLIP2 / DINOv2 / BGE 嵌入；
     - 初始化：用各策略数据集里的成功轨迹；运行中成功执行会追加。
   - **执行日志 H**：完整时序记录。包括上下文、调用、消息与输出、观测、动作、反馈与错误、桥接、结果，以及进化动作、验证结果、是否保留。
   - **policy card** 随证据更新。
   - 检索方式：先按文本 top-K，再按视觉 top-K，都用余弦相似度。
   - 下次怎么用：作为路由证据、构造桥接、TAMP 轨迹增强、进化的证据。
   - 保留范围：只在同一任务的试验间保留（§5）。
   - 存储格式（文件还是数据库）：**未报告**。
9. **成本**：
   - **部分报告**：真机推理或规划 API 调用平均 4.6 s / 次，135 次试验平均每回合多出 67.4 s 延迟（§7）。
   - token、美元、仿真侧调用次数与延迟：**未报告**。
   - Memory Bridge 候选搜索上限 10 s（附录 C.2）。
