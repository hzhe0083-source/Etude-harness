## 证据标注规范

- **〔全文〕/〔摘要〕**：照搬 v1 卡片上的证据级别，标在行首的系统名或出处后面。
- **（补读 §x）**：本次从 `https://arxiv.org/html/<id>` 正文补读，后面给节号、表号或附录号。只用于 B-1 里 A 层的 9 篇 arXiv 论文；A2 GPT-6 Astra 报告没有 arXiv 页，没有补读。
- **（v1 …）**：内容直接来自 v1，括号里是 v1 给的节号或表号；v1 没给节号时写"（v1 A?，节号 v1 未记录）"。
- **推断**：判断，不是论文结论。"推断（v1）"表示 v1 原文就是判断；只写"推断"的是本稿的判断。
- **v1 未记录**：v1 没写，而且没有补读（B 层条目、A2 报告），或者 v1 没写、本次也没有补读。**论文未写明（补读）**：补读过正文，论文本身也没写。

1. **上层规划器**：最常见的是前沿闭源模型或 coding agent，出现在 HarnessVLA、Astra、CaP-Agent0、ENPIRE、ASPIRE、Long-WAM；AOR 和 SHAPER 是 v1 写明"冻结模型/多模态 LLM"但没写型号。按调用时机分三类：
   - 在线每原语、每段或每轮调用：HarnessVLA、Astra、CaP-Agent0。
   - 只在回合开头调用：VERITAS，2 次。
   - 只在离线进化或学习阶段调用：Zetta 的进化 agent、ASPIRE、ENPIRE、RHO。

   没有单独规划器的是 RECAP（VLA 内部低频预测子任务）和 LWD。PhyAgentOS 和 Zetta 都没写明实际用的是哪个 LLM。
2. **动作接口**：冻结 VLA 当原语或基础策略的有 HarnessVLA、Astra、Zetta、PhyAgentOS、VERITAS（推理时）、Long-WAM；π0.5 出现在 HarnessVLA、Astra、Zetta、PhyAgentOS、VERITAS、LWD 六个系统里。生成代码的有 CaP-X、ASPIRE、AOR、RHO；ENPIRE 部分如此。训练权重的有 RECAP、LWD、VERITAS（BC）、CaP-RL、ENPIRE、Guava。
3. **记忆**：Markdown 或纯文本文件最多，见 PhyAgentOS 的 KNOWLEDGE/LESSONS.md、ASPIRE 的 SKILL.md、Zetta 的 SKILL.md、ENPIRE 的摘要、HarnessVLA 的 Global Memory。JSONL 和 JSON 只有 HarnessVLA 的 TSM 明确用了。代码库形式有 Zetta 的 tools/、ENPIRE 的 Git、RHO 的仓库、CaP-Agent0 的 9 个函数。存进权重的有 RECAP、LWD、VERITAS、CaP-RL、Guava。
4. **critic / 验证器**：在线每步或每段判断的有 Zetta（代码 critic）、VERITAS（几何打分）、Astra（大模型 gate）、HarnessVLA（规划器每个原语后判断，加停止谓词）。事后判断的有 PhyAgentOS（会话结束时）和 ENPIRE（每回合奖励函数）。只在训练期用的有 RECAP 和 LWD 的价值网络。实现形式上，代码有 Zetta、ENPIRE、VERITAS，模型有 Astra、RECAP、LWD、CaP-Agent0 的 VDM，基准谓词有 HarnessVLA、ASPIRE、CaP-X 仿真。
5. **失败诊断**：最常见的是 LLM agent 读结构化 trace，见 HarnessVLA、Zetta、PhyAgentOS、CaP-Agent0、ASPIRE、ENPIRE、AOR。其中 Zetta 写得最细，有聚类、中心 seed 和六层排查，也是唯一明确回查仿真内部状态的。RECAP 和 LWD 靠人工接管。VERITAS 没有诊断模块。
6. **技能库**：代码加文字的组合最多，见 ASPIRE、Zetta、PhyAgentOS 的技能规格、CaP-Agent0。VASO 用形式化契约。检索方式：ASPIRE 把整个库放进上下文；PhyAgentOS 用任务类型匹配加最近性的启发式；HarnessVLA、Zetta、CaP-X 都没写明。A 层里没有一篇报告嵌入式检索。
7. **接受门**：有明确多级门的是 Zetta 和 ASPIRE。Zetta 是"中心 seed 重跑 → 历史回归 100% → 留出 ΔSR"；ASPIRE 是"debug 集阈值 → 验证集 → 协调者审核 API 合规"。PhyAgentOS 要求后续结果证实，VASO 用模型检查。没有显式门的是 HarnessVLA（成功即写入）、LWD（每 50 步广播）、VERITAS（只做成功过滤）；RECAP 和 CaP-X 论文未写明。
8. **版本与回滚**：写了版本化的有 Zetta（harness 包）、ENPIRE（Git 分支）、LWD（数据快照）、PhyAgentOS（append-only，记录记忆版本）。RECAP 每轮从预训练检查点重训。所有系统都没写明回滚流程。
9. **复位与结果判定**：仿真里基本都用基准谓词或环境成功函数，见 HarnessVLA、Zetta（里程碑）、ASPIRE、CaP-X、ENPIRE 的 RoboCasa 部分、PhyAgentOS。真机上靠人工的有 RECAP、LWD、HarnessVLA。真机自动判定加自动复位的只有 ENPIRE（agent 自写）。PhyAgentOS 的验证器可以推翻基准的判定。
10. **成本记账**：报 token 的有 ENPIRE（MTU、Tokens to Success）和 ASPIRE（只报真机部分）。报延迟或时间的有 Zetta、HarnessVLA（Table 7）、CaP-X（App. K.2）、VERITAS、LWD（数据链路延迟）。报 GPU 型号或数量的有 Zetta（两处写法不同）、VERITAS。RECAP、PhyAgentOS、Astra 报告没有成本数字。
11. **仿真真值和 RESET**：
    - 明确读真值或特权信号的：Zetta（诊断时；运行时信号来自仿真器属推断）、CaP-RL（训练用 S1）、HarnessVLA（每步的基准成功信号）。
    - 明确禁止读真值的：ASPIRE（禁读 API 清单）、HarnessVLA（不读物体位姿）、VERITAS（构造上不需要）。
    - 探索期能 RESET 或重跑 seed 的：HarnessVLA、ASPIRE、Zetta、ENPIRE（真机自动复位）。
12. **开源**：有代码仓库链接的有 HarnessVLA、Astra 报告、PhyAgentOS、ENPIRE；VERITAS 的链接疑似占位。只有项目页的有 Zetta、ASPIRE、LWD、CaP-X（capgym.github.io）。RECAP 只有第三方实现。B 层 7 篇 v1 都没记录。
