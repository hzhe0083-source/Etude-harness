# M2 预注册：条件 3，记忆回路

依据 `docs/design/vla_harness_v1.md` 第 5 节 M2 列、3.1 节记忆回路和第 6 节条件 3。数值写在 `experiments/M2/config.yaml`，表格写在 `view.json`。

## 设计原文（§5 M2 列，逐字）

- **文件**：`memory/{store,writer}`；打乱记忆对照开关
- **实验**：E 上积累 → seed 0/1 评；对照 = 打乱记忆（换任务或打乱节点顺序）
- **预注册通过**：SR2(seed1) − SR1(seed1) ≥ ε；打乱记忆 ≤ SR1 + δ
- **预算（本机）**：约 500 回合 ≈ 33 h，约 $150
- **卡点**：记忆序列在 random 布局上可执行（坐标已换查询）

## 设计
| 项 | 取值 |
|---|---|
| 记忆积累 | 只在 E（开发任务 seed 0）积累，来源是 M1 h1 的 seed 0 回合 |
| 入库条件 | 离线官方 judge 成功 ∧ 全节点 Pass ∧ schema 通过（无数值 target） |
| 去重 | 同任务同指令哈希只留一条，保留更短的序列 |
| 写入者 | `memory/writer.py`，离线，不用 LLM |
| 评测期 | 记忆冻结，做哈希审计（§8.3） |
| 条件 h2 | H1 加只读记忆检索，top-3 |
| 条件 shuffled | 检索结果换成另一个开发任务的条目（换任务）。设计允许"换任务或打乱节点顺序"二选一，本预注册选换任务；打乱节点顺序作备选，不另跑 |
| 任务与 seed | 两个开发任务，seed 0 和 1。seed 0 是样本内结果，只记录，不进判据 |
| 对照 | M1 的 condition=h1 单元格，同布局配对 |

## 主分析

1. SR2(seed 1) − SR1(seed 1) ≥ ε。ε 取 M1 A/A 的结果。
2. 打乱记忆的 SR 不超过 SR1 + δ。δ 取 M1 A/A 的 δ_AA，即三次重跑成功数的最大成对差。

## 通过标准（§5 原文）

> SR2(seed1) − SR1(seed1) ≥ ε；打乱记忆 ≤ SR1 + δ

## 证伪条件（§6 原文）
| 条件 | 统计量 | 余量 | 后果 |
|---|---|---|---|
| 条件 3 在留出上缩水 | 开发任务 seed 2：SR2 − SR1 | < −δ_AA | 序列泄漏布局信息，回查 schema |

开发任务的 seed 2 属于 T 划分，T 只看一次（§3.2）。所以这一行的检查推迟到 M3 末，和 T 同一次查看。

## 附加检查

Gen 任务的 random 半场单列 SR，用来确认序列里的坐标都已换成 `perceive("…")` 查询（§7）。

## 预算

总量 500 回合（§5）：
- h2：2 个任务 × 2 个 seed × 50 = 200
- shuffled：2 × 2 × 50 = 200
- 剩下 100 回合留给补充的 E 积累

上限 33 h、$150。
