# Research OS v1：为什么只保留小台账

后来者需要先知道数据有多少、覆盖多少任务、训练用了哪个版本以及核心 loss、评测用了哪个 checkpoint 和评测代码版本以及成功率。完整日志是解释和复核这些结果的材料，随产物放在 Hugging Face，避免源码仓库随日志量增长。

ledger.json 保存当前结构化记录，Git 保存台账的历史版本。现有 reducer 只处理一次 CLI 更新，继续复用权限、依赖、失效传播和表格规则，不再回放完整事件文件。保存通过文件锁与原子替换完成；5 MiB 总量和 32 KiB 单记录上限拒绝把原始明细塞入台账。

源码版本由已推送的 Git commit 唯一确定，启动前拒绝未提交源码，运行使用独立 checkout。Python/依赖锁和输入校验值仍是复现条件，代码 commit 不能替代它们。评测代码 commit 与被测模型的 HF revision 是两个不同版本，分别记录。

运行结束与上传结束分开：退出码先落盘，原始记录上传并核验后设置 archive_status=uploaded。网络失败只需重试归档；失败实验也保留日志。每次外部中断后增加 attempt，不增加实验条件；改代码修复则创建带 supersedes 的新 Run。

指标采用白名单：数据量/任务数、训练或验证 loss、评测成功次数/总次数/比例。完整训练曲线、每样本结果、发布清单、检查报告均在 HF。旧记录缺失的 loss 不从训练步数推断，旧的未提交源码缺口也不会因迁移而消失。

旧 ARTIFACTS 的原始字节已按所属 Run 归档至对应 HF 仓库。一次性 migrate-ledger 命令消费经核验的导出状态和 HF 映射；正常运行没有旧存储格式的读取/写入 fallback。Git 历史保留，无需为本次约 12 MB 的旧数据重写历史。

完整操作约定见 [AGENTS.md](AGENTS.md)，具体字段见 [SCHEMA.json](SCHEMA.json)。
